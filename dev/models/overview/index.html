Models overview

Every model in the package has the same core:

outcome = race (or stage) level + driver effect + machine-season effect + noise

They differ in what the outcome is, which rows they can use, and how they model the noise.

ModelRows usedNoiseStatus
Z-score modellead-lap finishersGaussian, σ fixed at 1port of the original Python model, kept as the parity reference
Gap modelfinishers, lapped cars as intervalsStudent-t(4) or Gaussiansuperseded by pace + loss
Pace + lossas the gap modelGaussian pace noise + exponential incident lossesthe main model; many optional terms
Retirement modelevery startcompeting-risks hazardscomplements the pace models
Lap-time modelclean laps, F1 1996–pace + loss, per lapin development (#12)

Which pace model to use

The best race-time model by PSIS-LOO (as of #14) is the pace + loss model with every term on:

fit_paceloss(g; loss_duration = true, era = :rw, pace_scale = true, age = true,
             big_loss = true, slopes = true, dev = true)        # "pl_dur_rw_kappa_age_big_slope_dev"

Each term was added in its own issue and kept because it improved out-of-sample fit (expected log predictive density, elpd). The issues hold the comparisons:

TermOptionModel-name suffixIssue
race duration in the lossloss_duration_dur#9
incident rate and size drift over seasonsera = :rw_rw#9
pace scale by seasonpace_scale_kappa#15
population age curveage_age#15
big incident lossesbig_loss_big#16
per-driver career slopesslopes_slope#15
in-season development (+155.7 ± 16.4 elpd)dev_dev#14

The scripts and the model-comparison helpers name models by these suffixes (see model_spec). As the models grow, more rows get Pareto k > 0.7, so PSIS-LOO becomes less reliable; confirm close calls with grouped K-fold (see Model comparison).
